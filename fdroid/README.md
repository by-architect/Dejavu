# Publishing Dejavu on F-Droid

F-Droid compiles every app itself, from public source, and ships only what came out of that compile.
This guide is the plan for getting Dejavu there, and the steps to repeat for every release after.

| File | What it is |
| --- | --- |
| `com.byarchitect.dejavu.yml` | The first recipe, the one in the merge request today. It builds this whole repository and is being replaced (see below) |
| `mozconfig` | Build configuration with GeckoView compiled from source, not downloaded |
| `geckoview-prefs.js` | Default preferences the F-Droid build bakes into GeckoView |

The store listing F-Droid reads lives at the top of the repository in `fastlane/metadata/android/`,
generated by `scripts/dejavu-fastlane.sh` in the project folder.

## How Fennec F-Droid is built, and how Dejavu will be

[fennecbuild](https://gitlab.com/relan/fennecbuild) is the repository behind Fennec F-Droid. It holds
no browser code at all, only:

- `prebuild.sh` and `build.sh`, the two scripts the recipe runs, and `paths.sh`, which they share
- about 17 patches, for example `fenix-liberate.patch`, `gecko-liberate.patch` and
  `m-c-liberate.patch`, which take Google's and Mozilla's closed services out
- overlay folders and artwork that are copied over the source, plus `fastlane/` for the store listing

The Firefox source comes in as a **srclib**: F-Droid checks out
`FIREFOX-ANDROID_<version>_RELEASE` from <https://github.com/mozilla-firefox/firefox>, and the same
for application-services, Glean, UnifiedPush, microG and the toolchains. Srclibs are not scanned the
way the app's own repository is, which is why Fennec needs no `scanignore`. Its maintainer, relan,
updates fennecbuild within days of each Firefox release.

Dejavu will be a fork of fennecbuild with one extra patch, `dejavu.patch`, holding everything Dejavu
changes on top of the Firefox release. The patch is not written by hand: a script makes it from this
repository, so this repository stays where all the work happens, and the fork only carries the
result.

```
this repository (Dejavu)                      fork of fennecbuild (new repository)
  FIREFOX-ANDROID_159_0_RELEASE  --+
                                   |  diff
  v1.6.0 (Dejavu release tag)    --+------->  patches/dejavu.patch  ->  tag v1.6.0
                                                                          |
fdroiddata recipe: srclib MozFennec@FIREFOX-ANDROID_159_0_RELEASE  +  fork @ v1.6.0
```

The alternative is to keep this repository as the source and only take fennecbuild's scripts. It is
less work per release, but it is what the reviewer turned down, so only bring it up again if the
patch turns out unworkable.

## What is already right

- **Licence.** `LICENSE` is the full Mozilla Public License 2.0 text.
- **Public repository.** <https://github.com/by-architect/Dejavu>.
- **Its own identity.** The app is `com.byarchitect.dejavu`, named Dejavu, with its own icon and
  `mobile/android/branding/unofficial`. F-Droid turns away apps that use another project's
  trademarks, so Firefox's name and logo stay out.
- **A version code that does not move.** `mobile/android/fenix/app/build.gradle` computes it from the
  version name: 2016190000 + major * 10000 + minor * 100 + patch, so 1.0.0 is 2016200000 and 1.5.0 is
  2016200500. `-PversionCode` overrides it.
- **Closed libraries are separated.** The Google Play, Firebase, Adjust and install-referrer
  libraries live in `mobile/android/fenix/app/proprietary.gradle`. Without that file the app
  compiles `src/foss/java`, whose stand-ins keep every caller working, so an F-Droid build only has
  to delete it.
- **No keys in the build.** The token files the Fenix build reads are listed in `.gitignore`.
- **No Google dependency blob.** `dependenciesInfo { includeInApk = false }` keeps the signed
  metadata block out of the APK.
- **A store listing in 86 languages,** with the icon, feature graphic and screenshots.

## Publishing steps (first time)

Start on or after 2026-10-27, once Firefox 159 is out.

### 1. Move Dejavu onto Firefox 159

- Fetch the release tag: `git fetch https://github.com/mozilla-firefox/firefox tag FIREFOX-ANDROID_159_0_RELEASE`.
- Merge it into `main` (merge, never rebase), fix the conflicts, build and test on a phone.
- Release it as usual and push the tag, for example `v1.6.0`.

### 2. Fork fennecbuild

- Wait until relan has pushed the fennecbuild update for 159 (check the tags on
  <https://gitlab.com/relan/fennecbuild/-/tags>).
- Fork it on GitLab as `by-architect/dejavubuild` (any name; it is a new repository, separate from
  Dejavu).
- Clone it into `referanced-repos/` only to read it; work in a clone under `branches/` or a folder of
  its own.

### 3. Make the Dejavu patch

Write `scripts/dejavu-fdroid-patch.sh` in the project folder. It should:

- diff `FIREFOX-ANDROID_159_0_RELEASE` against the Dejavu release tag with `git diff --binary`;
- leave out what only belongs to this repository: `README.md`, `docs/`, `.github/`, `fdroid/`,
  `fastlane/` and anything F-Droid's scanner would reject (images can go into the fork's overlay
  folders instead, as fennecbuild does with its artwork);
- delete `mobile/android/fenix/app/proprietary.gradle` from the result, so the FOSS stand-ins are
  what gets built;
- write `patches/dejavu.patch` in the fork and copy `fastlane/` over the fork's `fastlane/`.

Check that the patch applies cleanly on a fresh checkout of the Firefox tag with `git apply --check`.

### 4. Adapt prebuild.sh and build.sh

- Apply `dejavu.patch` first, then fennecbuild's own patches.
- Change the app id rewrite from `.fennec_fdroid` to `com.byarchitect.dejavu`, and let it take
  Dejavu's version name and code.
- Drop Fennec's branding and artwork steps; Dejavu brings its own.
- Go through the liberation patches one by one. Several touch the same lines as Dejavu's
  `proprietary.gradle` split, so either Dejavu's version or fennecbuild's has to win. Keep
  fennecbuild's for GeckoView and application-services, which Dejavu has not changed.
- Use `fdroid/geckoview-prefs.js` where fennecbuild sets its own GeckoView preferences.

### 5. Build it locally

- In a local fdroiddata checkout, point the recipe at the fork and run
  `fdroid build -v -l com.byarchitect.dejavu`.
- The first full build compiles Gecko, Rust and the toolchains from source and takes hours. Note
  how long it takes.
- Check the APK with `aapt2 dump badging`: no `com.adjust`, `c2dm` or `finsky` permissions.
- Install it on a test phone (not the daily one with the Play release) and try it.

### 6. Update the recipe

Base it on `metadata/org.mozilla.fennec_fdroid.yml` from fdroiddata, not on the old recipe here:

- `Repo:` the fork, `commit:` its tag.
- `srclibs:` MozFennec@FIREFOX-ANDROID_159_0_RELEASE and the others Fennec uses.
- `sudo:` add `apt-get install -y rustup`, and remove the rustup srclib.
- No `scanignore` at all.
- `versionName`/`versionCode` from the Dejavu release, `UpdateCheckMode: None`.
- Copy the result into `fdroid/com.byarchitect.dejavu.yml` here, so this folder keeps the real one.

### 7. Push and answer the reviewer

- Push the recipe to the `com.byarchitect.dejavu` branch of `by-architect/fdroiddata`.
- Watch the pipeline with `scripts/fdroid-pipeline-watch.sh`.
- When it passes, reply on the merge request with what changed for each of the three requests.

## Every release after that

1. Release Dejavu and push its tag.
2. Run `scripts/dejavu-fdroid-patch.sh` for the new tag and commit the patch to the fork.
3. Tag the fork with the same version.
4. Add a `Builds:` entry to the recipe and update `CurrentVersion` and `CurrentVersionCode`.
5. Open a merge request on fdroiddata (after inclusion, updates are small merge requests too).

When a new Firefox version comes out, merge it into Dejavu first, then pull relan's fennecbuild
update into the fork, then do the steps above.

## Lessons from the first recipe

- **CI formats YAML differently from a released fdroid.** CI uses fdroidserver master with Debian's
  ruamel.yaml, which wraps a long `output:` value onto its own line; fdroid 2.4.3 does not, so
  `fdroid rewritemeta` passes locally and fails in CI. Commit the wrapped form, with its trailing
  space, as `org.mozilla.fennec_fdroid.yml` does.
- **`UpdateCheckMode: Tags` cannot work.** `checkupdates` reads every AndroidManifest.xml it finds,
  and the Firefox tree has hundreds in tests, so it gives up. Fennec uses `None` for the same reason.
- **The scanner rejects the whole Firefox tree.** Built from this repository, it found 3,627
  problems: Windows import libraries in `third_party/rust`, test binaries, WebAssembly and archives.
  That is what the srclib route avoids.
- **Anti-features.** A browser that can install add-ons from addons.mozilla.org and fetch OpenH264
  from Cisco must keep those downloads opt-in. Compare the `AntiFeatures` Fennec declares and use the
  same where Dejavu behaves the same.
- **One CPU architecture.** arm64-v8a only is allowed. Each extra architecture needs its own
  `Builds:` entry and version code below 2100000000, so the version code scheme has to change before
  a second one is added.
