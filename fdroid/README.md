# Publishing Dejavu on F-Droid

F-Droid compiles every app itself, from the source in the app's own public repository, and ships only
what came out of that compile. Nothing is accepted that it cannot build, read and rebuild. That makes
the bar higher than Google Play's, and Dejavu does not clear it yet.

This folder holds the two files that get it there:

| File | What it is |
| --- | --- |
| `mozconfig` | The build configuration for F-Droid: GeckoView compiled from this tree, not downloaded |
| `com.byarchitect.dejavu.yml` | A draft of the entry that goes into [fdroiddata](https://gitlab.com/fdroid/fdroiddata), the recipe F-Droid builds from |

The store listing F-Droid reads lives at the top of the repository in `fastlane/metadata/android/`,
generated by `scripts/dejavu-fastlane.sh` in the project folder.

## The rules

- [Inclusion Policy](https://f-droid.org/en/docs/Inclusion_Policy/) - what an app has to be
- [Submitting to F-Droid](https://f-droid.org/docs/Submitting_to_F-Droid_Quick_Start_Guide/) - how it gets in
- [Build Metadata Reference](https://f-droid.org/docs/Build_Metadata_Reference/) - every field in the recipe
- [Reviewing new apps](https://gitlab.com/fdroid/wiki/-/wikis/Internal/Reviewing-new-apps) - the checklist the reviewers work through

The four questions a reviewer asks first: is there a public repository with a free software licence,
are all the dependencies free software, is the toolchain free software, and does the author agree to
being included.

## Where Dejavu stands

### Already right

- **Licence.** `LICENSE` is the full Mozilla Public License 2.0 text.
- **Public repository.** <https://github.com/by-architect/Dejavu>.
- **Its own identity.** The app is `com.byarchitect.dejavu`, named Dejavu, with its own icon, and
  `mobile/android/confvars.sh` points at `mobile/android/branding/unofficial`. F-Droid turns away
  apps that use another project's trademarks, so not shipping Firefox's name or logo matters.
- **A version code that does not move.** `mobile/android/fenix/app/build.gradle` works it out from
  the version name, so 1.0.0 is always 2016200000. F-Droid pins the code in the recipe and throws the
  build away if the APK carries a different one, which the old clock-based Fennec code would have.
- **No keys in the build.** The token files the Fenix build reads are listed in `.gitignore`.
- **No Google dependency blob.** `dependenciesInfo { includeInApk = false }` keeps the unreadable
  signed metadata block out of the APK. Bundles keep it, because Google Play reads it.
- **A store listing in 86 languages,** with the icon, feature graphic and four screenshots.

### Blocking

**1. Closed-source libraries are linked into the release build.** This is the one that matters most;
nothing else can be submitted until it is done. In `mobile/android/fenix/app/build.gradle`:

| Line | Dependency | What it is |
| --- | --- | --- |
| 25 | `com.google.android.gms.oss-licenses-plugin` | Google Play services plugin |
| 570 | `:components:lib-push-firebase` | Firebase Cloud Messaging |
| 573 | `:components:lib-integrity-googleplay` | Google Play Integrity |
| 581 | `libs.adjust` | Adjust, a closed-source marketing attribution SDK |
| 628 | `libs.installreferrer` | Google Play install referrer |
| 632-633 | `libs.play.review`, `libs.play.review.ktx` | Google Play in-app review |
| 634 | `libs.play.services.ads.id` | Google advertising ID |

They are really in the shipped APK, not just in the build file. `aapt2 dump badging` on
`builds/dejavu-1.0.0-universal.apk` shows the permissions they declare:
`com.adjust.preinstall.READ_PERMISSION`, `com.google.android.c2dm.permission.RECEIVE` and
`com.google.android.finsky.permission.BIND_GET_INSTALL_REFERRER_SERVICE`.

Turning the features off at runtime is not enough: F-Droid's objection is to the library being there
at all, because its source cannot be read or rebuilt.

**2. GeckoView is downloaded, not built.** The mozconfig used day to day sets
`--enable-artifact-builds`, which fetches a compiled Gecko from Mozilla's servers. The 160 MB
`libxul.so` in the released APK came from there. F-Droid cannot ship a binary it did not build.
`fdroid/mozconfig` is the replacement, but it has never been run: a full Gecko build takes hours and
needs the Rust, clang, NDK and wasi-sdk toolchains, so budget a day for the first one.

**3. There is no release tag.** F-Droid builds a tag, and the recipe names the commit it points at.
`git tag v1.0.0 && git push origin v1.0.0` on the commit that was released.

**4. The toolchain question.** `./mach bootstrap` downloads Mozilla's own builds of clang, rust, the
NDK, node and wasi-sdk. They are the toolchain this source is meant to be compiled with, but they are
downloaded binaries, and the reviewer will ask about them. IronFox, the other Gecko browser on
F-Droid, builds wasi-sdk and llvm from source for its F-Droid builds and uses prebuilt ones only
locally. Raise it on the merge request rather than hoping it passes.

**5. One CPU architecture.** The release is built for arm64-v8a only, and each extra architecture is
another full Gecko build. Shipping arm64 alone is allowed; 32-bit ARM devices simply will not see the
app. Adding more means one `Builds:` entry per architecture, each with its own version code, and the
codes have to stay below Android's ceiling of 2100000000 - there is not much room above 2016200000,
so the scheme in `build.gradle` needs a rethink before a second architecture is added.

**6. Anti-features.** Until the libraries above are gone, the entry would have to declare `Tracking`
and `NonFreeDep`, the way Fennec F-Droid declares `Tracking` for its Mozilla connections. Once they
are gone, a browser that can install add-ons from addons.mozilla.org and fetch OpenH264 from Cisco
still needs those downloads to be opt-in, because F-Droid does not allow an app to pull in executable
code without the user clearly choosing it.

## What F-Droid's own pipeline says

The recipe was pushed to the `com.byarchitect.dejavu` branch of
<https://gitlab.com/by-architect/fdroiddata> and F-Droid's CI ran against it. Everything that checks
the metadata passes: `fdroid lint`, `fdroid rewritemeta`, `checkupdates`, the git-redirect check,
schema validation, YAML 1.2, EXIF and the rest.

`fdroid build` fails, and it fails before compiling a single line:

```
ERROR: Could not build app com.byarchitect.dejavu: Can't build due to 3627 errors while scanning
```

F-Droid scans the whole checked-out tree for things it cannot read, and mozilla-central is full of
them:

| Count | What the scanner found | Mostly in |
| --- | --- | --- |
| 2804 | static libraries (`.a`) | `third_party/rust` (2826 of all findings) |
| 634 | binaries | `security/nss`, `testing/web-platform`, `dom/webgpu` |
| 69 | WebAssembly files | |
| 66 | ZIP archives | test fixtures |
| 14 | shared libraries | |
| 13 | unknown maven repositories | the objdir maven repo and `third_party/application-services` |
| 12 | gzip archives | |
| 10 | known non-free libraries | see below |
| 2 | compiled Java classes | |
| 1 | `DexClassLoader` | `mobile/android/geckoview/.../GeckoLoader.java` |

The scanner's list of non-free libraries is longer than the one above, because it also reads the
GeckoView and android-components build files:

```
libs.play.services.fido       mobile/android/geckoview/build.gradle
libs.mlkit.prompt             android-components/components/lib/llm-gemininano/build.gradle
libs.firebase.messaging       android-components/components/lib/push-firebase/build.gradle

libs.play.review              mobile/android/fenix/app/build.gradle
libs.play.review.ktx          mobile/android/fenix/app/build.gradle
libs.play.services.ads.id     mobile/android/fenix/app/build.gradle
libs.play.review(.ktx)        mobile/android/focus-android/app/build.gradle
```

Almost all of it turned out to be prunable. 2,803 of the 2,804 static libraries are Windows import
libraries in `third_party/rust/winapi-*-pc-windows-gnu`, which an Android build never links. The
rest is test suites, plus a handful of data files the app really does ship.

The recipe now clears them in two ways, and `prebuild` is the reason it works: fdroidserver runs
init, srclibs and `prebuild` inside `prepare_source`, and only scans afterwards in `build_local`, so
anything deleted in `prebuild` is gone before the scanner looks.

- **41 `rm -rf` lines in `prebuild`** take out the test suites and the Windows and macOS halves of
  the tree. Safe, because `fdroid/mozconfig` configures with `--disable-tests`, so the build system
  never walks into them.
- **7 `scanignore` paths** cover what cannot be deleted: `third_party/rust`, `third_party/python`
  and `third_party/application-services` are vendored with cargo checksums, so removing one file
  inside them breaks the build; `toolkit/components/pdfjs/content/web/wasm` holds the JBIG2,
  OpenJPEG and qcms decoders pdf.js ships; `services/settings/dumps` holds the Remote Settings
  dumps.

Together they account for all 3,585 file findings. What that leaves is the part no amount of
pruning fixes: the ten non-free libraries, four maven repositories the scanner does not recognise,
and one `DexClassLoader` in GeckoView.

This is also why a separate build repository is not required. Fennec F-Droid uses one because it is
a thin patch set over a Firefox release tarball, which suits a patch series. Dejavu is a feature
fork - the rename commit alone was 278 files and 33,502 lines - so fork-and-merge stays the right
model, and the scanner is handled in the recipe instead.

## Two things the pipeline taught us

- **CI formats YAML differently from a released fdroid.** It installs fdroidserver master against
  Debian's ruamel.yaml, which wraps a long `output:` value onto its own line; fdroid 2.4.3 locally
  leaves it on one line, so `fdroid rewritemeta` passes here and fails there. The wrapped form, with
  its trailing space, is what to commit - `org.mozilla.fennec_fdroid.yml` has the same shape.
- **`UpdateCheckMode: Tags` cannot work here.** `checkupdates` looks for the version by reading every
  AndroidManifest.xml in the tree, and mozilla-central has hundreds of them in tests, so it gives up
  with "Couldn't find any version information". Fennec F-Droid sets `UpdateCheckMode: None` for the
  same reason, and so does this recipe.

## Removing the libraries

Thirteen files import them:

```
components/Components.kt                              play.core review, Play Integrity
components/PlayStoreReviewPromptController.kt          play.core review
components/ipprotection/IPProtection.kt                Play Integrity
push/FirebasePushService.kt                            Firebase messaging
components/metrics/ActivationPing.kt                   Google advertising ID
components/metrics/MetricsUtils.kt                     Google advertising ID
components/metrics/AdjustMetricsService.kt             Adjust
components/metrics/AdjustSdkController.kt              Adjust
components/metrics/AdjustThirdPartySharingController.kt  Adjust
components/metrics/DefaultInstallReferrerClient.kt     install referrer
components/metrics/InstallReferrerClientWrapper.kt     install referrer
components/metrics/InstallReferrerHandlingService.kt   install referrer
components/metrics/InstallReferrerWorker.kt            install referrer
```

The rest of the app talks to them through interfaces that already exist - `MetricsService`,
`concept-integrity`, `concept-push` - so they can be swapped rather than cut out. The approach that
disturbs Fenix least is to keep every caller where it is and give the `release` build type its own
source directory holding do-nothing versions of those classes, leaving the real ones to the `nightly`
and `beta` builds:

```groovy
sourceSets {
    release.java.srcDirs += 'src/foss/java'
    nightly.java.srcDirs += 'src/proprietary/java'
    beta.java.srcDirs    += 'src/proprietary/java'
    debug.java.srcDirs   += 'src/proprietary/java'
}
```

Then the dependencies move from `implementation` to `nightlyImplementation` and `betaImplementation`,
and `Components.kt` gets the review prompt and the integrity client from a small factory that each
source directory provides.

This has not been done. It needs a working Gecko build to compile against, which is also what
blocker 2 needs, so do them in the same sitting.

The merge request is open as a draft:
<https://gitlab.com/fdroid/fdroiddata/-/merge_requests/50786>

Every metadata job passes. The source scan went from 3625 errors to 15, and the 15 that are left are
not binaries at all - they are the non-free libraries plus the in-tree maven repository, which is
scanignored. What remains:

1. Take out the ten non-free libraries, or replace them with microG stubs the way Fennec F-Droid
   does. Four are in the Fenix module, two in `lib-push-firebase`, one in GeckoView
   (`play-services-fido`), one in `lib-llm-gemininano` which the app never reaches, and two in
   `focus-android`, a different app that shares the tree.
2. Get an answer on the merge request to the two structural questions: whether `mach bootstrap`
   downloading Mozilla's clang, rust, NDK, node and wasi-sdk is acceptable, and how to express a
   build that runs for hours.
3. Get one full build out of `fdroid/mozconfig` locally and note how long it takes, so the timeout
   asked for is a measured number.
4. Rebuild and check with `aapt2 dump badging` that the Adjust, c2dm and finsky permissions are gone.
5. Take the MR out of draft.
